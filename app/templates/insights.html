A model that always predicts "no failure" would be {{ '%.1f'|format(d.baseline_accuracy_if_always_no_failure * 100) }}% accurate, so accuracy is not used to choose between models. How to read these metrics
Recall
Of the machines that really failed, the share the model flagged. A missed failure means unplanned downtime, so recall is the metric to protect.
Precision
Of the machines flagged, the share that really failed. Low precision means false alarms and wasted inspections.
F1
The balance of precision and recall in one number.
PR-AUC
How well the model ranks failures above normal machines, focusing on the rare failure class. The main selection metric. A random model scores about {{ '%.3f'|format(d.test_failures / d.test_rows) }}.
ROC-AUC
Ranking quality over all thresholds. It looks flattering on imbalanced data, so read it together with PR-AUC.
Brier score
Average squared error of the predicted probabilities (lower is better). It checks that "70%" really means about 70%, which the alert thresholds rely on.

How the models were built

Procedure and reproducibility

The data was split once into {{ d.train_rows }} training and {{ d.test_rows }} test machines (stratified: {{ d.train_failures }} and {{ d.test_failures }} failures). Every choice (features, imbalance handling, hyperparameters, calibration, ensemble weights, default model) used 5-fold cross-validation on the training machines only. The test set was used once, to report the figures above. Later sections (baselines, results for each failure type, missed failures) read it afterwards for description only; no model or threshold was changed because of them. Threshold and tool-wear comparisons use cross-validation on the training machines. Any future change should be judged the same way (see ml/twf_study.py), with the test set looked at once at the end. Scaling, resampling and encoding are fitted inside each training fold.
